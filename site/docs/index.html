Server configuration reference

The laminardb binary reads a TOML configuration file, constructs streaming pipelines, and serves a REST API with Prometheus metrics. Server and checkpoint defaults are checked against server config and engine config. This page describes the v0.33.0 release. Last updated: 19 October 2026.

Install

v0.33.0 is the current release. Release assets are named laminardb-server-<target>-v0.33.0.tar.gz (.zip for x86_64-pc-windows-msvc) for the targets x86_64-unknown-linux-gnu, aarch64-unknown-linux-gnu, x86_64-unknown-linux-musl, x86_64-apple-darwin, aarch64-apple-darwin and x86_64-pc-windows-msvc, with a SHA256SUMS file. The commands below link to the v0.33.0 tag so that they keep working after later releases.

Install & run
BASE=https://github.com/laminardb/laminardb/releases/download/v0.33.0
curl -fLO "$BASE/SHA256SUMS"

# Linux x86_64
ASSET=laminardb-server-x86_64-unknown-linux-gnu-v0.33.0.tar.gz
curl -fLO "$BASE/$ASSET"
grep " $ASSET\$" SHA256SUMS | sha256sum -c -
tar xzf "$ASSET"

# macOS Apple silicon (instead of the Linux lines above)
ASSET=laminardb-server-aarch64-apple-darwin-v0.33.0.tar.gz
curl -fLO "$BASE/$ASSET"
grep " $ASSET\$" SHA256SUMS | shasum -a 256 -c -
tar xzf "$ASSET"

# Run the binary (the archive contains the laminardb executable)
./laminardb --config laminardb.toml

# Or build from a source checkout (laminar-server is not published to crates.io)
git clone https://github.com/laminardb/laminardb.git
cd laminardb && git checkout v0.33.0
cargo build --release -p laminar-server
./target/release/laminardb --config laminardb.toml

# Or Docker. The image's built-in config binds 0.0.0.0:8080 and reads
# console_token from LAMINAR_CONSOLE_TOKEN; the server exits without it.
export LAMINAR_CONSOLE_TOKEN="$(openssl rand -hex 32)"
docker run -d -p 8080:8080 -e LAMINAR_CONSOLE_TOKEN \
  -v laminardb-data:/var/lib/laminardb \
  laminardb/laminardb-server:0.33.0

The image runs laminardb --config /etc/laminardb/laminardb.toml. To add pipelines, mount your own file there (for example -v "$PWD/laminardb.toml:/etc/laminardb/laminardb.toml:ro"); keep a console_token, because a container needs a non-loopback bind. Its built-in checkpoint directory is file:///var/lib/laminardb/checkpoints. The image sets LAMINAR_DISABLE_FILE_WATCH=1, so call POST /api/v1/reload after editing a mounted config. The :latest and :main tags are rolling builds of the main branch, not releases.

Cluster Config

Source: crates/laminar-server/src/config/mod.rs, cluster_config.rs

When mode = "cluster", the server requires a unique top-level node_id, a [discovery] section with seeds, and a [checkpoint] url on shared object storage (s3://, gs:// or az://). Cluster coordination uses that checkpoint store; there is no separate [coordination] section or embedded Raft service.

Cluster mode rejects best_effort delivery, local paths and file:// checkpoints (peers cannot recover them), and a checkpoint.interval below 100ms. At-least-once requires replayable input and a durable sink. Cluster exactly-once supports Kafka input with either an S3/S3A append-mode Delta Lake sink or a REST-catalog Iceberg append sink backed by S3/S3A storage.

[discovery]

seeds Array<String> [] Gossip address of every node, including this one (e.g. ["10.0.0.1:7946", "10.0.0.2:7946"]). Required for both strategies; expected membership is derived from it.

advertise_host String none Host or IP this node advertises to peers. If unset: the host part of [server].bind; for a wildcard bind (0.0.0.0, ::) the machine hostname; 127.0.0.1 only if the hostname is empty.
failure_domain String none Locality gossiped to peers for placement: a flat label ("rack17") or coarsest-first ;-separated tiers ("region=...;zone=...;rack=...").
placement_isolation_tier usize 0 Locality tier the placement and blast-radius metrics group by (0 = coarsest).
cluster_tls_cert Path none PEM certificate for control-plane (barrier/shuffle) mTLS.

[server]

[checkpoint]

[discovery]

seeds = ["10.0.0.1:7946", "10.0.0.2:7946"]

A single-node server with replay-capable delivery and an s3://, gs:// or az:// checkpoint fails with [LDB-0014]: a shared cloud checkpoint namespace is not admitted for one node until its writer lease is term-fenced. A file:// checkpoint directory is locked by one process at a time.

Memory Limits & Production Tuning

The limits above are independent admission budgets. DataFusion reservations are shared per DB/node; source queue bytes are shared per DB/node; graph input limits apply to each port; reference-table and materialized-view limits apply to each local table or view. They do not sum to a process RSS cap. Connector decoding, direct Arrow allocations, managed state, query results, checkpoint encoding, restore staging and allocator overhead need separate headroom.

Managed operator working state has a default 256 MiB charged-byte budget. Set [server].pipeline_max_managed_state_bytes to change it (embedded users set the same field through LaminarConfig or the builder). Its charge is a lower bound, not total resident memory. Local reference tables and materialized views are unavailable in cluster plans that require distributed ownership.

Size a deployment

  1. Run representative peak input, bursts and a fault/restart cycle with the intended SQL and connectors. Measure peak process or container RSS, source lag and checkpoint duration.
  2. Observe /metrics: laminardb_cycles_backpressured_total, laminardb_input_buf_bytes, laminardb_managed_state_accounted_bytes, laminardb_checkpoint_size_bytes, laminardb_checkpoints_failed_total and laminardb_checkpoint_duration_seconds. Use OS or container RSS (on Linux, laminardb_process_resident_memory_bytes) for the actual memory envelope.
  3. Set container memory requests and limits above the measured peak with room for Arrow and connector scratch, simultaneous old/new state on recovery, and checkpoint capture. The Helm chart defaults to resources: {}; supply workload-specific values.
  4. If admission saturates, examine batch size and downstream throughput before raising queue or graph-port limits. A result too large for a port after execution faults the pipeline. Size checkpoint.max_node_data_bytes above the largest expected participant artifact and verify recovery at that setting.

checkpoint.interval defaults to 10s and trades replay work against checkpoint traffic. checkpoint.timeout defaults to 120s; keep it above observed attempt duration. Changes to [server] and [checkpoint] require a restart (see Hot Reload). The main I/O runtime uses TOKIO_WORKER_THREADS (logical CPU count by default), while streaming compute uses one dedicated thread. On the default non-MSVC build, jemalloc can be tuned with MALLOC_CONF at process start; see the allocator guidance.

Console UI & Control API

Source: crates/laminar-server/src/http/router.rs

The Console UI is a web client that lets you inspect your streaming SQL nodes, view lineage dependency graphs, and author queries. You can access the hosted console at laminardb.github.io/laminardb-console-ui.

The console connects to the control-plane APIs exposed by the server. When server.console_token is configured, every /api/v1/* route and /ws/{name} requires it. /health, /ready and /metrics are always public so probes and scrapers work without a token; restrict network access to them.

Security & Gating

  • HTTP Authentication: Send the configured token in the header: Authorization: Bearer <token>. Duplicate or comma-joined bearer values are refused.
  • WebSocket Authentication: Browsers cannot set headers on the upgrade request, so /ws/{name} also accepts ?token=<token>. The query parameter is accepted only on /ws/ routes.
  • CORS Gating: Restrict client origins using the server.console_cors_allowed_origins array in TOML. Without it the CORS policy is permissive.
  • TLS: The HTTP listener has no TLS settings; terminate TLS at a trusted proxy.

WebSocket Subscription Protocol

Source: crates/laminar-server/src/http/ws.rs

Connect to GET /ws/{name}, where name is a stream; add ?as_of_epoch=N to start from a committed epoch instead of the tail. Each text frame is a JSON object with a type. subscription_id is the stream name, and all counters are sent as decimal strings. Data frames carry at most 1 MiB, so a large batch is split across frames using row_offset/row_count: 

{
  "type": "data",
  "subscription_id": "vwap",
  "data": [ { "symbol": "AAPL", "vwap": 178.5 } ],
  "sequence": "42",
  "log_sequence": "17",
  "row_offset": "0",
  "row_count": "1"
}

Other frame types: progress (epoch, checkpoint_id, log_sequence, through_log_sequence, sequence), gap (the subscriber lagged; code = subscription_lagged, skipped_messages) and error (code, message). In cluster mode data frames also carry stream_generation, partition, partition_sequence and committed_epoch. The server sends a WebSocket ping every 15 seconds and closes the connection after two unanswered pings. The server accepts at most 10,000 WebSocket connections.

Cluster Management Endpoints

  • GET /api/v1/cluster/nodes — Cluster members: id, name, rpc_address, state (Joining, Active, Suspected, Draining, Left), metadata and last_heartbeat_ms.
  • GET /api/v1/cluster/vnodes — The durable key-group (vnode) assignment snapshot.
  • GET /api/v1/cluster/leader — The current leader's node record (if known) and whether this node is the leader.
  • GET /api/v1/cluster/checkpoints — Latest checkpoint status; also available in single-node mode.
  • GET /api/v1/cluster/topology and /api/v1/cluster/topology/* — Durable catalog version, topology validation, migration submission, preparation, status and legacy-catalog adoption (see the REST table below).

/api/v1/cluster, /nodes, /vnodes and /leader return 404 when the server is not in cluster mode.

REST API

Source: crates/laminar-server/src/http/router.rs

The server exposes an HTTP API on the configured bind address. All responses are JSON except /metrics (Prometheus text format). The first three routes are public; the rest require the console token when one is configured. Until startup completes, and in cluster mode during coordinated recovery, routes other than the three probes return 503.

Hot Reload

Source: crates/laminar-server/src/reload/mod.rs

Edit the TOML config file while the server is running. A file watcher detects changes (500ms debounce, content-hash comparison), diffs the old and new configs, and applies incremental DDL. Or trigger manually via POST /api/v1/reload; a second reload while one is running returns 409.

What reloads without restart: [[source]], [[lookup]], [[pipeline]] and [[sink]] entries (add, remove, or change).

What requires restart: [server], [checkpoint], [discovery], [supervision], [[process_function]], [ai], [models], the top-level sql string and node_id. The reload response carries a warning for each of these that changed.

Reload does not touch certificates. The pgwire listener watches its own pgwire_tls_cert, pgwire_tls_key and pgwire_tls_client_ca files and swaps them in when they change; a failed reload keeps the previous certificate.

Reload order: remove changed/deleted sinks → pipelines → lookups → sources, then recreate sources → lookups → pipelines → sinks. Disable file watcher with LAMINAR_DISABLE_FILE_WATCH=1.

Connectors

In Rust builds, include the connectors you need with Cargo features, for example cargo add laminar-db --features kafka,delta-lake. These are build options, not runtime approval gates. The v0.33.0 server binaries and Docker image include every connector below.

Set delivery once at [server].delivery (or LaminarDbBuilder::delivery_guarantee when embedded). The runtime injects the selected protocol and owns checkpoint/committer identities; connector properties do not require public writer IDs.

Set the serialization format with the SQL FORMAT clause (... FROM KAFKA (...) FORMAT JSON) or the TOML format field. A 'format' connector option is rejected: "option 'format' is unsupported; declare the format with the FORMAT clause". Format-specific options go in FORMAT fmt WITH (...).

RabbitMQ, IBM MQ, FIX and FpML connectors are optional build features and are not in default builds or the Docker image. The v0.33.0 x86_64 Linux (glibc) binary includes all four, the x86_64 Linux (musl) binary none, and the other binaries FIX and FpML.

Known limitations in v0.33.0:

  • A json file must contain exactly one JSON object. Files with several JSON Lines records, or a top-level JSON array, fail to decode ("trailing characters" or "JSON value must be an object"), despite the jsonl/ndjson aliases.
  • A file that fails to decode is retried continuously, with a warning in the log each time, and stays at the head of the queue, so later files are not loaded.   • The CSV reader cannot decode TIMESTAMP columns; declaring one fails with "CSV reader ... cannot decode". Use BIGINT, DOUBLE, BOOLEAN, DATE or VARCHAR columns, or another format such as Parquet.

Generator Source

Source: generator/mod.rs

Emits a deterministic sequence with no external system, for demos and tests. It is always built in. Row i is (seq = i, ts_ms = i * 1000 / rows.per.second, value = "v{i}") with the fixed schema seq BIGINT NOT NULL, ts_ms BIGINT NOT NULL, value VARCHAR NOT NULL. Join Semantics

Bounded interval joins are the stateful stream-stream joins. Temporal joins look up the version of a keyed source that was valid at the probe row's event time. Lookup joins enrich a stream from a [[lookup]] table. Admission rejects unsupported join shapes before connector I/O. The rules below follow the SQL reference.

Join TypeStateScopeMatch
Bounded interval Keyed stream state Single node and cluster All pairs within the time bound
Temporal Versioned right-side history, keyed Single node and cluster Point-in-time lookup
Lookup Lookup table (replicated or on-demand cache) Single node (cluster rejects it) Key equality

Interval Join (Stream-Stream)

Source: laminar-db/src/interval_join/

Matches pairs of rows from two direct sources whose equality keys match and whose event times satisfy the directional predicate right.ts BETWEEN left.ts AND left.ts + bound, where the bound is a positive, finite interval. Both inputs need watermarks on TIMESTAMP NOT NULL event-time columns. Equality keys are one or more VARCHAR/BIGINT columns of matching types; NULL keys do not match.

Supported types: INNER, LEFT, RIGHT, FULL, LEFT/RIGHT SEMI, LEFT/RIGHT ANTI

Interval join — match orders to payments within 1 hour
CREATE STREAM matched AS
SELECT o.order_id AS order_id,
       o.amount AS amount,
       p.status AS status
FROM orders o
INNER JOIN payments p
    ON o.order_id = p.order_id
    AND p.ts BETWEEN o.ts AND o.ts + INTERVAL '1' HOUR;
  • Every projected expression needs an explicit alias, and every projected or filtered column must use its left/right qualifier.
  • Outer and anti unmatched rows are emitted only when the opposite input's watermark closes their possible match interval.
  • Joining and aggregating in one statement is not supported: name the join output and aggregate it in a separate stream.
  • Cross, unbounded, general non-equality, intermediate-input and multi-way joins are rejected on this path.

Temporal Join (FOR SYSTEM_TIME AS OF)

Source: laminar-db/src/operator/temporal_join/, laminar-sql/src/parser/join_parser/

For each left row, looks up the right-side row that was valid at the left row's event time, using SQL:2011 FOR SYSTEM_TIME AS OF. Runs in single-node and cluster mode for one direct two-input join. ASOF JOIN is not an alias.

Supported types: INNER, LEFT

Temporal join — currency rate valid at order time
CREATE STREAM converted_orders AS
SELECT o.order_id AS order_id,
       o.amount AS amount,
       r.rate AS rate,
       o.amount * r.rate AS converted
FROM orders o
JOIN currency_rates FOR SYSTEM_TIME AS OF o.order_time AS r
    ON o.currency = r.currency;
  • The left source must be append-only. The right source must declare its equality keys as its PRIMARY KEY; it may be append-only or keyed-upsert.
  • Both sides need watermarks on their event-time columns. A result becomes final only after the right watermark passes its probe time.
  • Set [server].temporal_join_idle_history_retention; a pipeline containing a temporal join requires it. It bounds right-side version history while an input is idle.

Lookup Join

Source: lookup_join.rs

Enriches stream rows from a lookup table by equality on its single-column primary key, with no time bound. A replicated table is held in memory; an on-demand table fetches missing keys from the connector and keeps them in a bounded memory cache (cache.memory, cache.ttl). With pushdown set to auto or enabled, predicates are pushed to the lookup connector. Cluster mode rejects lookup joins.

Supported types: INNER, LEFT

Lookup join — enrich orders with product info
SELECT o.order_id, o.amount, p.name, p.category
FROM orders o
LEFT JOIN products p
    ON o.product_id = p.id;

[supervision]

Source: config/mod.rs, laminar-db/src/config.rs

Single-node only. After a fatal pipeline fault, the server restarts the pipeline from the last checkpoint with exponential backoff, up to max_restarts times within the window; after that the pipeline stays faulted. Supervision is not enabled when [[process_function]] entries are configured. Changes require a restart.

AI Functions ([ai] and [models])

SQL functions such as ai_classify, ai_sentiment, ai_embed and ai_complete run a named model from a registry configured with [ai.providers.<name>], [models.<name>] and [ai.defaults]. See the server README AI section for the keys and an example.

  • AI functions are single-node only; cluster mode rejects them ([LDB-4007]).
  • Local (ONNX) models need ONNX Runtime 1.24 or newer installed on the host, on the library search path or via ORT_DYLIB_PATH. The Docker image does not include ONNX Runtime. Remote providers do not need it.
  • Remote providers read their API key from the environment variable named in api_key_env; the key is not stored in the config.
  • Changes to [ai] or [models] require a restart.

Environment Variables

Source: crates/laminar-server/src/config/mod.rs, laminar-db/src/ddl/source_sink.rs

Config file: before parsing, the server replaces ${VAR} and ${VAR:-default} anywhere in the TOML text with environment values, including inside [[pipeline]] SQL and the top-level sql string. A missing variable without a default is a startup error. Write $${VAR} to keep a literal ${VAR} in the loaded config so that it is resolved later, when the DDL runs.

Connector and format options in DDL: when a CREATE SOURCE, CREATE SINK or lookup-table statement runs, ${VAR} and ${VAR:-default} in its connector and format option values are resolved from the database's config variables (set with LaminarDbBuilder::config_var when embedded), then from the process environment. This also applies to DDL sent through POST /api/v1/sql or pgwire. An unresolved name without a default fails the statement. Other parts of SQL submitted at runtime are not substituted.

Environment variable examples
[source.properties]
"bootstrap.servers" = "${KAFKA_BROKERS:-localhost:9092}"
"sasl.username" = "${KAFKA_USER}"
"sasl.password" = "$${KAFKA_PASSWORD}"   # kept literal; resolved when the DDL runs

[checkpoint]
url = "s3://${S3_BUCKET}/checkpoints"   # cluster mode (single-node at_least_once needs file://)

[checkpoint.storage]
aws_access_key_id = "${AWS_ACCESS_KEY_ID}"
aws_secret_access_key = "${AWS_SECRET_ACCESS_KEY}"

Other variables read by the server: LAMINAR_DISABLE_FILE_WATCH=1 (or true) disables the config watcher, TOKIO_WORKER_THREADS sizes the I/O runtime, RUST_LOG overrides --log-level, and MALLOC_CONF tunes jemalloc.

Delivery Guarantees

Source: connector/contracts.rs, config/validation.rs
GuaranteeHow it worksRequirements
best_effort No replay promise. This is the low-latency mode for inputs or outputs that cannot survive a failure. Accepts ephemeral connectors; failure may lose accepted events.
at_least_once Server default. Recovery resumes replayable sources from the finalized checkpoint cut, so some records may be processed again. Checkpointing, replayable sources, and durably acknowledged sinks. Single-node mode needs a local file:// checkpoint directory (an object-store URL is rejected with [LDB-0014]). Cluster mode needs a cluster-shared s3://, gs:// or az:// checkpoint URL.
exactly_once Barrier-aligned state and source positions are sealed before checkpoint-committable sink output becomes externally visible. Single-node requires an exclusively locked local file:// checkpoint directory ([LDB-0014] otherwise), a replayable source with exact recovery, and a coordinated sink. Cluster mode requires a shared checkpoint URL and Kafka input with either an S3/S3A append-mode Delta Lake sink or a REST-catalog Iceberg append sink backed by S3/S3A storage. Kafka output is exactly-once in embedded and single-node mode through checkpoint-staged transactions and a fenced committer; cluster Kafka output remains at-least-once. Unsupported combinations fail before connector I/O.

Delivery is one pipeline-wide setting. Per-connector delivery fields are rejected, and incompatible connectors fail before external I/O. For example, the WebSocket, OpenTelemetry and NATS (Core and JetStream) sources are non-replayable and therefore require best_effort; they fail under the server default at_least_once. Cluster mode rejects best_effort. Cluster exactly_once admits Kafka input with an S3/S3A append-mode Delta Lake sink or a REST-catalog Iceberg append sink backed by S3/S3A storage.

Full Config Example

A single-node, at-least-once pipeline: a Kafka source read from the earliest offset, a one-minute VWAP window, and two sinks. Set LAMINAR_CONSOLE_TOKEN (at least 8 characters) and KAFKA_BROKERS before starting; a missing variable is a startup error. To add enrichment, define a [[lookup]] table and join it in a separate pipeline.

laminardb.toml
[server]
mode = "single"
bind = "0.0.0.0:8080"
console_token = "${LAMINAR_CONSOLE_TOKEN}"   # required for a non-loopback bind
delivery = "at_least_once"

[checkpoint]
# Single-node at_least_once / exactly_once need a local file:// directory.
url = "file:///var/lib/laminardb/checkpoints"
interval = "30s"

# --- Sources ---

[[source]]
name = "trades"
connector = "kafka"
format = "json"

[source.properties]
"bootstrap.servers" = "${KAFKA_BROKERS}"
topic = "market-trades"
"group.id" = "laminar-vwap"
"startup.mode" = "earliest"   # group offsets are rejected under at_least_once

[[source.schema]]
name = "symbol"
type = "VARCHAR"
nullable = false

[[source.schema]]
name = "price"
type = "DOUBLE"

[[source.schema]]
name = "volume"
type = "BIGINT"

[[source.schema]]
name = "ts"
type = "TIMESTAMP"
nullable = false

[source.watermark]
column = "ts"
max_out_of_orderness = "5s"

# --- Pipelines ---

[[pipeline]]
name = "vwap"
sql = """
SELECT symbol,
       tumble(ts, INTERVAL '1' MINUTE) AS window_start,
       SUM(price * CAST(volume AS DOUBLE)) / SUM(CAST(volume AS DOUBLE)) AS vwap,
       SUM(volume) AS volume
FROM trades
GROUP BY symbol, tumble(ts, INTERVAL '1' MINUTE)
EMIT ON WINDOW CLOSE
"""

# --- Sinks ---

[[sink]]
name = "kafka_output"
pipeline = "vwap"
connector = "kafka"
format = "json"

[sink.properties]
"bootstrap.servers" = "${KAFKA_BROKERS}"
topic = "vwap-1m"
"key.column" = "symbol"

[[sink]]
name = "archive"
pipeline = "vwap"
connector = "files"
format = "parquet"

[sink.properties]
path = "/var/lib/laminardb/archive/vwap"
